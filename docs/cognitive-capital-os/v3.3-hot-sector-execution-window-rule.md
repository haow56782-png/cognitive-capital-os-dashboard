# Cognitive Capital OS v3.3｜Hot Sector Execution Window Rule

> 目标：把盘中热点分析从“行情解释”升级为“可执行、可证伪、可复盘”的交易决策流程。

本规则是 Cognitive Capital OS v3.3 的强制执行层，必须与 Simons Validation Layer、Heatmap Evidence DB、Anchor Index Engine、Drift Detection Engine、Action Engine 联合使用。

---

## 1. 核心问题

过去系统容易出现的问题不是“看不出热点”，而是：

```text
信号判断正确，但买点窗口错了。
```

典型错误：

- 看到热点才追，买在高潮。
- 没有尾盘先手，次日盘中情绪补票。
- 只看单票，不看板块共振。
- 只看题材，不看中军和 ETF。
- 长期逻辑正确，但短线买点错误。
- 没有反证条件，错了还继续幻想。

因此 v3.3 新增 Hot Sector Execution Window Rule。

---

## 2. 宪法级规则

```text
热点不是买点。
信号也不是买点。
只有“信号 + 执行窗口 + 反证条件”同时成立，才是可交易机会。
```

硬性纪律：

```text
无执行窗口，不交易。
无板块共振，不交易。
无中军确认，不加仓。
无 ETF / 指数确认，不升级主线。
无反证条件，不执行。
无尾盘先手，不盘中硬追。
错过窗口默认等待，不补票。
```

默认禁止：

```text
20CM 小票、缩量一字、消息刺激、无中军确认的高位高潮追涨。
```

## 3. Hot Sector Execution Window DB 字段

| 字段 | 说明 |
|---|---|
| Date | 交易日 |
| Sector | 热点板块 |
| Ticker | 标的名称 / 代码 |
| Signal ID | 对应 Simons 信号编号 |
| Best Entry Window | 最佳执行窗口 |
| Current Window Status | 当前窗口状态 |
| Pre-position Required | 是否需要尾盘先手 |
| Chase Allowed | 是否允许盘中追 |
| Add-on Condition | 加仓条件 |
| Abort Condition | 放弃条件 |
| Missed Entry Handling | 错过窗口后的处理 |
| Final Action | 最终动作 |

### 3.1 Best Entry Window 枚举

```text
尾盘先手
盘中确认
回调承接
放量反包
禁止追高
```

### 3.2 Current Window Status 枚举

```text
未到
有效
已错过
等待确认
禁止执行
```

### 3.3 Chase Allowed 默认规则

默认：NO。

只有同时满足以下条件，才允许盘中追：

```text
1. 板块成片强。
2. 中军放量。
3. ETF / 指数跑赢。
4. 热力图持续前排。
5. 有明确反证条件。
```

## 5. 与 Simons Validation Layer 的关系

Simons Validation Layer 负责判断信号是否有统计价值。
Hot Sector Execution Window Rule 负责判断当前能不能交易。

二者关系：

```text
Signal 成立 ≠ 可以交易
Signal 成立 + 执行窗口有效 + 反证条件明确 = 可交易机会
```

示例：

```text
Signal：HUAWEI_SOFTWARE_PULLBACK_OBSERVE_V1
逻辑：华为软件生态回调观察
最佳窗口：尾盘先手 / 放量反包
当前窗口：已错过
Final Action：不追，等待下一窗口
```

## 6. 典型场景规则

### 6.1 华为软件 / AI 应用

适用标的：拓维信息、软通动力、润和软件、常山北明、神州数码等。

规则：

```text
无尾盘先手，不盘中硬追。
无软件开发 / IT 服务 / 数字媒体板块共振，不单票追。
无软通、润和、常山北明、神州数码等多点确认，不加仓。
```

### 6.2 华为韬定律 / 国产半导体硬件链

适用板块：半导体设备、先进封装、PCB、高速互连、EDA、半导体材料。

规则：

```text
只看泛华为小票，不执行。
必须看半导体ETF、元件、通信设备、电子化学品、先进封装是否成片前排。
必须看中军：北方华创、中微公司、沪电股份、胜宏科技、长电科技、华大九天、中科曙光。
```

### 6.3 机器人 / AI 物理世界执行层

适用标的：埃斯顿、拓斯达、汇川技术、双环传动、柯力传感、震裕科技、凌云光等。

规则：

```text
高位中军只做锚，不追。
等待回调承接、机器人ETF反包、人形机器人指数修复、中军放量确认。
```

### 6.4 消费 / 防御轮动

适用板块：白酒、旅游零售、食品饮料、机场、保险、电力、煤炭等。

规则：

```text
可以记录为防御轮动信号。
不能自动升级为长期主线。
不追高，验证 T+1 / T+3 持续性。
```

### 6.5 证券

证券是风险偏好放大器，不是普通产业主线。

规则：

```text
无指数放量，不追证券。
无东方财富、中信证券、华泰证券、同花顺等中军放量，不升级。
```

## 7. 尾盘先手规则

尾盘先手只在以下条件下允许：

```text
1. 标的处于回调承接区，而不是高位高潮。
2. 板块没有破位。
3. 尾盘资金回流。
4. 次日存在明确催化。
5. 反证条件明确。
6. 仓位上限明确。
```

否则输出：

```text
不给尾盘先手。
```

如果尾盘没有先手，次日盘中默认不能追，只能等待：

```text
1. 放量确认。
2. 回调承接。
3. 板块共振。
4. 中军确认。
```

## 10. 测试验收标准

### 用例一：盘中热点推荐

输入：热力图截图。

必须输出：

```text
热点板块
Signal ID
Best Entry Window
Current Window Status
Chase Allowed
Final Action
```

缺失任一字段，视为失败。

### 用例二：单只个股是否能买

输入：个股截图。

必须输出：

```text
所属热点
是否板块共振
是否中军
最佳窗口
是否错过
是否允许追
触发条件
反证条件
仓位上限
```

只回答“可以 / 不可以”，视为失败。

### 用例三：尾盘复盘

输入：14:30 后热力图。

必须判断：

```text
是否给尾盘先手
是否错过最佳窗口
次日是否只等确认
哪些热点禁止追
哪些板块进入 T+1 验证池
```

缺失“是否给尾盘先手”，视为失败。

